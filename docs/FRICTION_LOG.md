# AccessFlow — Friction Log (Amazon Developer Hackathon)

Friction encountered while building AccessFlow for the Fire TV track, with the workarounds used and actionable suggestions. Referenced from the Devpost submission (its Friction Log field accepts a URL).

## Entry 1
Task attempted: Validate a Fire TV experience against the track requirement (demo running on a Fire TV device or the Fire TV/Vega simulator). Steps taken: Read the track details and Resources on the hackathon page and the Fire TV developer documentation; looked for a hosted/browser simulator option that works without a full local development machine. Expected: A discoverable, lightweight official simulator or hosted validation path linked from the track resources. What actually happened: The resources point to local SDK/simulator setup. Working away from my development laptop during the submission window, I could not stand up the local toolchain, so I could not validate against the official simulator. Severity: High (blocked the intended validation path). Workaround used: Built a faithful web-based Fire TV experience prototype implementing the real engine (weighted navigation graph + Dijkstra + difficulty detection) end-to-end, deployed it publicly, and disclosed the prototype's nature openly in the submission and README. Actionable suggestion: Link a hosted Fire TV/Vega simulator (or a "validate a web-based Fire TV experience" path) directly from the hackathon Resources page, with a short checklist mapping it to the "demo video" requirement.

## Entry 2
Task attempted: Find developer guidance for motor-impairment accessibility on Fire TV. Steps taken: Searched the Fire TV accessibility and assistive-technologies documentation. Expected: Guidance covering input effort / motor accessibility alongside vision and hearing. What actually happened: Documented assistive technologies cover vision (VoiceView, magnification, text banner) and hearing (captions, audio streaming). No motor/navigation-effort guidance or API exists. Severity: Medium. Workaround used: Designed an original detection + adaptation model (press-level difficulty signals, weighted-graph optimization, approval-gated shortcut pinning) and validated it with measured before/after task runs. Actionable suggestion: Add a motor-accessibility section to the Fire TV accessibility docs — even documenting the gap and best-effort patterns (larger focus targets, shortcut pinning, recovery paths) would help developers design for these users.

## Entry 3
Task attempted: Sideload the built Fire TV wrapper APK onto Amazon's cloud Fire TV (Appstore Quality Central → Live Device Interaction) to record on-device footage for the demo video. Steps taken: Built a native Fire OS WebView-wrapper APK (fire-tv/, package com.arya.accessflow, target SDK 34) from the repo's web build on a Linux VM; opened developer.amazon.com in the available browser to sign in and start a cloud Fire TV session. Expected: Sign in to an Amazon Developer account, install the APK on a virtual Fire TV device, drive it with the virtual remote, and capture footage. What actually happened: Amazon's developer sign-in presented an AI-agent refusal page, so the session could never start. The block persisted when the user clicked the sign-in himself in that browser, confirming the block is on the browser environment, not on the user. No account was accessed and nothing was installed or changed. Severity: High (blocked the intended on-device validation/filming path on the final day). Workaround used: Kept the built APK and its full wrapper source in the repo as verifiable platform work, disclosed the device-farm block openly in the submission and video, and shot the demo from the faithful web-based Fire TV experience running the real engine. Actionable suggestion: Publish a supported headless/CI path for installing a debug APK on a cloud Fire TV for testing (e.g., an upload-and-run flow that does not require an interactive browser sign-in), so teams working away from their usual machines — including agent-assisted ones — can validate during short hackathon windows.
