# AccessFlow — User Study Kit (run on Oct 23, before final submission)
Goal: honest before/after numbers from real people — NOT one staged run.

## Who
- Target 5–10 participants: classmates/friends. If any participant genuinely has a motor impairment, note it (with their permission). Otherwise run ONE extra condition honestly labelled as simulation: participant uses their **non-dominant hand** (and optionally a thick glove) — report it as "simulated motor difficulty (non-dominant hand)", never as a disability.
- Each participant does the session on the same demo link: https://arya123-sudo.github.io/AccessFlow/

## Rules (read to every participant)
- "Navigate naturally. Don't try to make mistakes, and don't try to be perfect."
- NO coaching during tasks. NO staged overshoots — whatever happens, happens.
- Facilitator only records the numbers the demo itself displays.

## Tasks (same for everyone, in order)
- **Task A (baseline):** Turn on Subtitles. (Demo Task 1 flow)
- **Task B (adapted):** When AccessFlow proposes an adaptation, approve it, then turn on Subtitles again. (Demo Task 2 flow)
- **Task C:** Play the movie "River Run". (Demo Task 3)
- Optional Task D: Turn on High Contrast (Settings → Accessibility).

## Record per participant (from the demo's own metrics/results panels)
Participant #, condition (dominant hand / non-dominant simulation / other), per task: presses, errors, time. Then the results-panel before/after for A vs B.

## SUS questionnaire (after all tasks — standard System Usability Scale, answer 1–5)
1. I think that I would like to use this system frequently.
2. I found the system unnecessarily complex.
3. I thought the system was easy to use.
4. I think that I would need the support of a technical person to be able to use this system.
5. I found the various functions in this system were well integrated.
6. I thought there was too much inconsistency in this system.
7. I would imagine that most people would learn to use this system very quickly.
8. I found the system very cumbersome to use.
9. I felt very confident using the system.
10. I needed to learn a lot of things before I could get going with this system.
Scoring (standard): for odd items subtract 1; for even items subtract response from 5; sum × 2.5 = SUS score out of 100.

## Report honestly (template in results.csv + summary below)
- Report means for presses/errors/time: baseline vs adapted, % improvement, n = participants.
- Report mean SUS.
- State limitations in one paragraph: small convenience sample, simulation condition is not lived disability experience, prototype is a web-based Fire TV experience, tasks were short.
- Put the summary + a before/after chart in the README "User study" section and in the Devpost description update.
